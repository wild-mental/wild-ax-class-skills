# review-wild — Wild에게 중간 피드백 요청하기

학생이 **스스로 원해서** 중간 산출물에 피드백을 받고 싶을 때 쓴다.
"한번 봐주세요"를 Wild가 짧은 시간에 답할 수 있는 **초점 있는 요청**으로 바꾸는 것이 목표다.

**언어 규칙**: 학생이 쓰는 언어로 대화하고, 요청 본문도 학생의 언어로 쓴다.

## 다른 스킬과의 경계

| 학생의 상황 | 맞는 스킬 |
|---|---|
| 완성 전 작업물에 의견을 듣고 싶다 | **review-wild** |
| 과제 요건에 맞춘 최종본을 낸다 | submit-wild |
| 개념이나 문제 풀이에서 막혔다 | ask-wild |
| 작업물이 아니라 생각이나 주제를 이야기하고 싶다 | discuss-wild |

최종 제출이 목적으로 보이면 submit-wild를 안내하고, 학생이 그래도 피드백을 원하면 이 스킬로 진행한다.

---

## 불변 규칙

1. **학생의 명시적 승인 없이 아무것도 보내지 않는다.**
2. **작업물을 고치거나, 대신 완성하거나, 점수를 매기지 않는다.** 피드백은 Wild가 한다. 이 스킬은 요청을 잘 만드는 데까지만 돕는다.
3. **학생의 자기 평가를 대신 쓰지 않는다.** 학생이 말한 강점과 약점을 그대로 정리한다.
4. **요청 범위를 좁힌다.** 봐줄 측면은 최대 3개, 질문은 최대 3개. Wild의 시간을 존중하는 것이 좋은 피드백을 받는 길이라고 학생에게 설명한다.
5. **파일 첨부는 하지 않는다.** 작업물은 링크로 보낸다.
6. 암호·복호화된 주소 취급 규칙은 ask-wild와 같다.

## 워크플로

### 1) 요청 패킷 만들기

| 필드 | 내용 | 비고 |
|---|---|---|
| `work` | 작업물 이름 (관련 과제가 있으면 함께) | 필수 |
| `link` | 작업물 링크 | 필수 |
| `stage` | 아이디어 / 개요 / 초안 / 부분 완성 / 거의 완성 | 필수 |
| `focus` | 봐주셨으면 하는 측면 **1–3개** | 예: 구조, 논리 흐름, 근거, 방향성, 표현, 기술적 정확성, 디자인 |
| `questions` | 구체적인 질문 **1–3개** | 물음표로 끝남 |
| `self_check` | 스스로 생각하는 잘된 점 1개, 아쉬운 점 1개 | 학생의 말 그대로 |
| `skip` | 지금은 안 봐주셔도 되는 것 (선택) | 예: "맞춤법은 아직 안 다듬었어요" |
| `where` | 특히 봐주셨으면 하는 위치 (선택) | 예: "2–3쪽", "결론 문단" |
| `by_when` | 피드백이 있으면 좋은 시점 (선택) | 실제 마감이 있으면 함께. **3일보다 촉박하면** 아래 안내 |
| `ai_use` | AI 활용 내역 (선택) | 피드백 맥락에 도움이 되면 학생이 적음 |
| `since_last` | 지난 피드백 이후 바뀐 점 (재요청일 때만) | 1–2문장 |

**응답 시간 안내**: Wild 선생님은 리뷰 요청에 **평균 3일 이내**에 답한다. `by_when`이 3일보다 촉박하면 이 사실을 학생에게 그대로 알리고, 질문을 가장 중요한 1개로 줄이거나 일정을 조정할지 함께 정한다. 빠른 답을 약속하지 않는다.

**좋은 질문으로 다듬기**: "괜찮은가요?" 대신 "서론에서 문제 제기가 충분히 분명한가요?"처럼, Wild가 예/아니오와 이유로 답할 수 있게 다듬는다. 학생이 말하지 않은 걱정을 지어내지 않는다.

**보내기 전 자기 점검 (선택)**: 학생이 원하면 "이 질문에 스스로 먼저 답해 본다면?" 같은 점검 질문을 1–2개 던진다. 답을 대신 주지 않는다. 학생이 스스로 답을 찾으면 요청 자체가 필요 없어질 수도 있고, 그것도 좋은 결과다.

이름과 소속 조는 `profile get`으로 먼저 확인한다(시리즈 공용 프로필). 이름이 없으면 미리보기 뒤의 **학생 안내** 한 번으로 묻고 `profile set --name "…" --team "…"`로 저장한다(소속 조가 없다고 하면 `--team` 없이 저장). **반은 묻지 않는다**(반 암호로 자동으로 정해진다).

### 2) 공유 설정 검사 (필수)

작업물 링크를 **Wild 선생님이 로그인 없이 열 수 있는지** 검사한다. 판정은 스크립트가 하고, Claude는 공유 상태를 수집해 넘기기만 한다. 기준은 submit-wild와 같고, 피드백 요청이므로 **댓글 작성자 권한을 권장**한다(편집자여도 통과).

| 서비스 | 통과 | 불통과 |
|---|---|---|
| Google Docs·Sheets·Slides·Drive | 링크가 있는 모든 사용자 (뷰어·댓글 작성자·편집자) / 웹에 게시된 링크 | 제한됨(초대한 사람만) · 특정 조직만 |
| Notion | 웹에 게시된 링크(`…notion.site/…`) / Wild 선생님을 초대 | 워크스페이스 링크(`notion.so/…`)인데 초대하지 않음 |
| GitHub | 공개 저장소 / Gist(공개·비밀) / Wild 선생님 계정을 공동 작업자로 초대 | 비공개 저장소인데 초대하지 않음 |
| 그 밖의 서비스 | 로그인하지 않은 창에서 열림 | 로그인 요구 또는 접근 거부 |

**상태 수집 순서**

1. **Google 링크이고 학생의 Drive 커넥터가 있으면** (링크 공개뿐 아니라 Wild 선생님 계정에 직접 공유한 경우도 통과한다. 그래서 설정의 `qna_email`을 `--accept-user`로 넘긴다): 파일 권한을 조회해 결과 JSON을 그대로 넘긴다. 학생에게 묻지 않는다.

   ```bash
   python3 <skill_dir>/scripts/check_share.py "<link>" --purpose review --accept-user "<payload의 qna_email>" --permissions-stdin <<'JSON'
   <Drive 커넥터의 파일 권한 조회 결과 JSON>
   JSON
   ```
2. **Notion 링크**: 주소만으로 판정한다. 상태 없이 실행한다. `notion.so` 링크로 불통과가 나왔는데 학생이 Wild 선생님을 초대했다고 하면 `--reported notion_invited`로 다시 판정한다.
3. **그 밖의 경우**: 상태 없이 실행해 `report_options`와 `verify_steps`를 얻고, 학생에게 공유 창 상태를 고르게 하거나 시크릿 창에서 열어 보게 한 뒤 `--reported <상태>`로 다시 판정한다.

```bash
python3 <skill_dir>/scripts/check_share.py "<link>" --purpose review
```

Drive 커넥터 없이 Google 링크를, GitHub 커넥터 없이 GitHub 링크를 검사하게 되면 **부록 B**에 따라 해당 커넥터 연결을 안내한다(지금 검사는 학생 확인으로 계속).

**판정 처리**

| `verdict` | 행동 |
|---|---|
| `pass` | 진행. `reasons`에 댓글 작성자 권장 안내가 있으면 한 줄로 전한다 |
| `fail` | 아래 **자동 공유**가 가능하면 먼저 제안한다. 아니면 `reasons`와 `fix_steps`를 단계별로 안내하고, 학생이 고치면 같은 방법으로 다시 검사한다 |
| `unverified` | 3번 방법으로 상태를 받아 다시 판정한다 |

**자동 공유 (Google 링크 + 학생 Drive 커넥터)**: 결과에 `auto_share`가 있고 학생의 Drive 공유 도구가 있으면, 고치는 방법을 안내하기 전에 먼저 이렇게 묻는다.

> 선생님이 열 수 있도록, 이 파일을 **Wild 선생님 계정에 보기 권한으로 공유**해 둘까요? 다른 사람에게는 공개되지 않아요.

- 동의하면 `auto_share`의 `file_id`, `email`, `role`(`reader`) 그대로 Drive 공유 도구를 호출한다. **다른 대상이나 더 높은 권한으로 바꾸지 않는다**(링크 공개·편집 권한 금지).
- 공유한 뒤 파일 권한을 다시 조회해 같은 명령으로 재검사한다. 통과하면 "선생님 계정에 보기 권한으로 공유했어요"라고 한 줄로 알린다.
- 학생이 거절하거나 공유가 실패하면(파일 소유자가 아님, 학교 계정의 외부 공유 차단 등) `fix_steps` 안내로 넘어간다.

**GitHub 링크**: `--github-user "<payload의 github_username>"`을 함께 넘긴다.

- 학생의 GitHub 커넥터로 저장소 정보를 조회할 수 있으면 공개 여부를 `--repo-visibility public|private|internal`로 넘긴다. 없으면 상태 없이 실행해 `report_options`에서 고르게 하거나 시크릿 창으로 확인하게 한 뒤 `--reported github_public|github_private`로 다시 판정한다.
- Gist(`gist.github.com`)는 공개·비밀 모두 링크로 열리므로 바로 통과한다.
- **비공개 저장소로 불통과**이면 `github_options.ask` 그대로 **두 가지 중 하나를 고르게** 한다.
  1. **공개로 전환**: `option_public` 단계를 안내한다. 공개 전에 비밀번호·개인정보가 없는지 확인하라는 문장은 빼지 않는다.
  2. **Wild 선생님 계정 초대**: `option_invite` 단계를 안내한다. 학생 환경에 `gh` CLI가 있으면(Claude Code 등) 동의 한 번을 받고 `gh_invite_command`를 실행해도 된다. 초대 후 `--reported github_invited`로 다시 판정한다.
- 초대를 고른 경우, **선생님이 수락하셔야 열린다**는 점을 알리고 본문의 공유 설정 칸에 `초대함(수락 대기)`으로 적는다. 마감이 가까우면 공개 전환이 더 확실하다고 한 번 말해 준다.

두 번 고쳐도 통과하지 못하면 그대로 보낼지 멈출지 학생이 정한다. 그대로 보내면 본문에 `공유 설정 ✘ (<reason>)`을 적는다.

### 3) 미리보기와 승인

```
제목: [review-wild]<work>-[<반 라벨>][<team>][<name>]

Wild 선생님, 안녕하세요. <name>입니다.
진행 중인 <work>에 대해 중간 피드백을 부탁드리고 싶습니다.

■ 작업물: <link>  (단계: <stage>, 공유 설정 <✔ 또는 ✘ (사유)>)
■ 봐주셨으면 하는 부분: <focus>  (<where>)
■ 질문:
   1) <question 1>
   2) <question 2>
■ 스스로 본 점: 잘된 점 – <...> / 아쉬운 점 – <...>
(■ 지금은 안 보셔도 되는 것: <skip>)
(■ 희망 시점: <by_when>)
(■ AI 활용: <ai_use>)
(■ 지난 피드백 이후 바뀐 점: <since_last>)

— review-wild로 정리해 보낸 요청입니다.
```

영어로 쓸 때는 `Work / Stage / Please focus on / My questions / My own take / Please skip for now / By when / AI use`를 쓴다.
제목 태그 `[review-wild]`는 항상 유지한다.

**학생 안내 (짧게)**: 첫 미리보기에서 반 라벨·소속·이름이 아직 비어 있으면 빈칸 그대로 보여 주고, 필요한 것만 아래처럼 **한 번에** 묻는다(잠금 여부는 부록 A의 `status`·A-1로 먼저 확인해, 이미 열려 있으면 반 암호는 묻지 않는다). 이미 알고 있는 항목은 문장에서 뺀다.

> 제목의 빈칸을 채우려면 **반 암호(비밀키)**와 **이름**이 필요해요. 소속 조가 있으면 함께 알려 주세요(없으면 `[개인]`으로 표기돼요).

제목이 어떻게 만들어지는지(반 라벨, 슬롯, 자동 입력 등)는 설명하지 않는다. 학생이 물을 때만 답한다.

### 4) 채널 설정 열기

**부록 A** 절차로 채널 설정을 연다. 대부분은 학생에게 묻지 않고 자동으로 열린다.

### 5) 채널 생성과 전송

```bash
python3 <skill_dir>/scripts/compose.py --config <skill_dir>/config/channels.enc.json --skill review-wild <<'JSON'
{"subject": "[review-wild] <work>", "body": "<미리보기 본문>",
 "fields": {"name": "…", "team": "<소속, 없으면 생략>", "topic": "<work> (<stage>)",
            "message": "<focus> / <questions>",
            "details": "<self_check> / <skip> / <where> / <since_last>",
            "link": "<link>", "when": "<by_when>", "ai_use": "<ai_use>"}}
JSON
```

| 순서 | 조건 | 행동 |
|---|---|---|
| ① 메일 커넥터 | 학생의 메일 발송 도구가 있음 | 발송. 초안 도구만 있으면 초안을 만들고 [보내기]를 안내 |
| ② Google Form | ①이 불가하고 `form_url`이 있음 | 미리 채워진 링크 제시 → [제출]만 누르도록 안내 |
| ③ mailto | ①②가 불가 | 링크와 함께 본문 전체를 복사용으로 제공 |

①을 쓸 수 없어 ②·③으로 넘어가면, **부록 B**에 따라 Gmail 연결을 한 번 안내한다.

**반 라벨과 소속**: 메일·폼·mailto에는 `compose.py` 출력의 `subject`·`body`를 **그대로** 쓴다. `compose.py`에는 제목을 `[<skill>] <주제>`까지만 넘기면, 반 라벨·소속(`fields.team`)·**학생 이름**(`fields.name`)이 자동으로 붙어 `[<skill>]<주제>-[<반 라벨>][<소속>][<학생 이름>]` 형태가 된다(소속 조가 없으면 `[개인]`). 반은 학생이 입력한 반 암호의 슬롯 라벨이므로 **학생에게 묻거나 제목에 따로 적지 않는다.** 본문 끝에는 `(반: <반 라벨> · 소속: <소속 또는 개인>)`, 폼의 Class 칸에는 `<반 라벨> · <소속>`이 들어간다. 그래서 `fields.name`은 반드시 채운다(프로필 이름). 미리보기에서도 이 제목 그대로 보여준다.

### 6) 마무리

- 어느 채널로 보냈는지 한 줄로 알린다.
- **"Wild 선생님은 평균 3일 이내에 답해 주세요."** 라고 응답 기대 시간을 알린다.
- 같은 작업물로 다시 요청해도 된다고 알린다. 횟수 제한은 없다. 다만 다음 요청에는 지난 피드백을 어떻게 반영했는지 한 줄을 넣으면 Wild가 이어서 보기 쉽다.
- 피드백을 기다리는 동안 작업을 멈출 필요는 없다고 알린다. 다만 질문한 부분은 크게 바꾸지 않는 편이 피드백을 활용하기 쉽다.
- 피드백을 받은 뒤 반영 계획을 함께 세우고 싶으면 다시 불러 달라고 안내한다.

## 문제 해결

| 증상 | 조치 |
|---|---|
| 학생이 "그냥 전부 봐주세요"라고 함 | 가장 불안한 부분 하나를 고르게 돕는다. 그래도 정하지 못하면 `focus`를 "전체 방향성"으로 두고 질문 1개로 시작한다 |
| 학생이 Claude에게 직접 피드백을 원함 | 그것은 이 스킬의 범위가 아니라고 알리고, 원하면 일반 대화로 돕는다. 이 스킬로 보내는 요청에는 섞지 않는다 |
| 종료코드 `3` / `4`, `python3` 실행 불가 | ask-wild와 같음 |

## 부록 A. 채널 설정 열기 (wild-series 공통)

모든 wild 스킬이 같은 절차를 쓴다. `<skill_dir>`는 이 SKILL.md가 있는 폴더, `<skill>`은 이 스킬의 이름(`review-wild`)이다.

```bash
python3 <skill_dir>/scripts/wild_vault.py status --config <skill_dir>/config/channels.enc.json --skill review-wild
```

| `state` | 행동 |
|---|---|
| `ok`, `refreshed`, `series` | 열림. 학생에게 묻지 않는다. (`series`는 다른 wild 스킬에서 이미 입력한 반 암호로 열린 것) |
| `no-cache` | **A-1** 학생용 접속 토큰을 스스로 찾는다 |
| `revoked` | "선생님이 이 반 암호의 사용을 중지하셨어요. 새 암호를 받아 입력해 주세요" → **A-2** |

### A-1. 학생용 접속 토큰 찾기 (학생에게 묻기 전에)

**학생용 접속 토큰**은 학생이 반 암호를 처음 입력했을 때 발급되는 한 줄이다: `WILD-TOKEN v3 <series-id> <token>`.
암호가 아니며, 선생님이 그 반 암호를 회수하면 자동으로 무효가 된다. 시리즈 전체(ask·meet·review·discuss·submit)에서 한 줄로 쓰인다.

아래 순서로 찾고, 처음 찾은 곳에서 멈춘다. **학생에게 아무것도 묻지 않는다.**

1. **현재 맥락**: 학생의 개인 선호 설정, Project 지침·파일, 이번 대화.
2. **과거 대화**: 과거 대화를 검색하는 도구가 있으면 `WILD-TOKEN`으로 검색한다.
3. **학생의 Google Drive**: Drive 검색 도구가 있으면 이름이 `wild-series 접속 토큰`인 파일을 찾아 내용을 읽는다.

찾은 줄(여러 개면 모두)을 stdin으로 넘긴다:

```bash
python3 <skill_dir>/scripts/wild_vault.py token import --config <skill_dir>/config/channels.enc.json --skill review-wild <<'TOKEN'
WILD-TOKEN v3 <series-id> <token>
TOKEN
```

- 성공 → 열림. 학생에게 "저장된 접속 토큰으로 접속했어요" 한 줄만 알린다.
- 종료코드 `3`(회수됨/무효) 또는 아무 데서도 못 찾음 → **A-2**.

### A-2. 반 암호로 잠금 해제

미리보기의 **학생 안내**에서 이미 받았으면 다시 묻지 않는다. 아니면 학생에게 **"Wild 선생님께 받은 반 암호(비밀키)를 입력해 주세요"** 라고 요청하고, stdin으로 넘긴다 (명령행 인자로 넘기지 않는다):

```bash
python3 <skill_dir>/scripts/wild_vault.py unlock --config <skill_dir>/config/channels.enc.json --skill review-wild <<'PW'
<학생이 입력한 반 암호>
PW
```

- 종료코드 `2`(wrong password): 다시 요청. **3회 실패** 시 중단하고 본문을 복사용으로 주며 "Wild 선생님께 암호를 다시 확인해 주세요"라고 안내.
- 성공 → 열림. 출력의 `"suggest_token": true`이면 **A-3**.
- 처음 연 경우 **부록 B**의 "처음 쓸 때" 안내를 한 번 한다.

### A-3. 접속 토큰 발급과 자동 보관

```bash
python3 <skill_dir>/scripts/wild_vault.py token export --config <skill_dir>/config/channels.enc.json --skill review-wild
```

**학생이 직접 할 일을 최소화한다.** 아래 a는 항상 하고, b는 가능하면 하고, c는 a·b가 모두 불가능할 때만 한다.

| 방법 | 조건 | 행동 | 학생이 할 일 |
|---|---|---|---|
| **a. 대화 기록에 남기기** | 항상 | 발급된 토큰 줄을 이번 대화에 한 번 보여준다: "학생용 접속 토큰이 발급됐어요. 다음 대화에서는 제가 이 기록을 찾아 자동으로 접속할게요." | 없음 |
| **b. 학생 Drive에 저장** | Drive 파일 생성 도구가 있음 | "다음부터 확실하게 자동 접속되도록, 학생님 Google Drive에 토큰 파일을 저장해 둘까요?" **한 번** 묻고, 동의하면 `wild-series 접속 토큰` 문서를 만든다(내용: 토큰 줄 + 아래 설명). 같은 이름의 파일이 있으면 새로 만들지 않고 내용을 바꾼다. 공유 설정은 바꾸지 않는다 | "네" 한 번 |
| **c. 개인 선호에 붙여넣기** | a의 과거 대화 검색 도구도, b의 Drive 도구도 없음 | "설정 → 프로필 → 개인 선호에 아래 한 줄을 붙여 두면 다음부터 자동으로 접속돼요"라고 안내 | 붙여넣기 한 번 |

c로 넘어가면 **부록 B**에 따라 Google Drive 연결도 함께 안내한다(다음부터 토큰을 자동으로 보관·복원할 수 있다).

토큰 파일·안내에 함께 쓰는 설명: "학생용 접속 토큰입니다. 암호가 아니며, 선생님이 반 암호를 회수하면 자동으로 무효가 됩니다. 다른 사람과 공유하지 마세요."

- 학생이 b나 c를 거절하면 다시 묻지 않는다.
- A-1에서 이미 같은 시리즈의 유효한 토큰을 찾았다면 A-3은 생략한다.
- A-1에서 찾은 토큰이 회수되어 A-2로 새로 발급했다면, b로 저장해 둔 Drive 파일도 새 토큰으로 바꾼다.
- Claude Code(로컬)에서는 `~/.wild-skills` 캐시가 유지되므로 `suggest_token`이 `false`이고 A-3을 하지 않는다.

## 부록 B. 커넥터 연결 안내 (wild-series 공통)

커넥터가 연결돼 있으면 Claude가 확인과 처리를 직접 해서 **학생이 할 일이 줄고 결과가 정확해진다.** 그래서 이 스킬은 필요한 커넥터가 없으면 **항상 연결을 안내**한다.

| 커넥터 | 연결하면 자동으로 되는 것 | 쓰는 스킬 |
|---|---|---|
| **Gmail** | 요청·제출을 학생 메일로 바로 발송 (폼·복사 단계 없음) | 전체 |
| **Google Drive** | 공유 설정 검사, 선생님 계정 자동 공유, 접속 토큰 보관 | submit · review (토큰 보관은 전체) |
| **Google Calendar** | 수업일을 읽어 면담 가능한 시간만 보여줌 | meet |
| **GitHub** | 저장소 공개 여부 확인 | submit · review |

**언제 안내하나**

1. **처음 쓸 때**: 채널 설정을 연 직후(부록 A), 이 스킬이 쓰는 커넥터 중 지금 도구 목록에 없는 것을 한 번에 묶어 알린다.
2. **필요한 순간**: 커넥터가 없어 예비 경로(폼 링크, 학생 확인, 시크릿 창 확인, 수업일 직접 고르기 등)로 넘어갈 때, 그 자리에서 "이 단계는 ○○ 커넥터를 연결하면 자동으로 돼요"라고 한 줄로 알린다.

**규칙**

- 같은 대화에서 같은 커넥터는 **한 번만** 안내한다. 학생이 "나중에"라고 하면 그 대화에서는 다시 말하지 않는다.
- 안내 때문에 진행을 멈추지 않는다. **지금 일은 예비 경로로 계속**하고, 학생이 연결한 뒤 원하면 그 단계부터 다시 한다.
- 연결 여부는 Claude의 도구 목록으로 판단한다. 학생에게 "연결돼 있나요?"를 먼저 묻지 않는다.

**안내 문구** (학생 언어로)

> 이 단계는 **<커넥터>** 를 연결하면 제가 직접 확인해 드릴 수 있어요.
> Claude **설정 → 커넥터**에서 <커넥터>를 연결하고, 대화 입력창의 도구 메뉴에서 켜 두면 돼요. 지금은 다른 방법으로 계속할게요.
