# submit-wild — Wild에게 과제 제출하기

학생이 과제를 **빠짐없이, 같은 형식으로** 제출하도록 돕는다.
Wild 입장에서는 열리지 않는 링크, 초안 버전, 빠진 설명 같은 제출 사고가 줄어든다.

**언어 규칙**: 학생이 쓰는 언어로 대화하고, 제출 본문도 학생의 언어로 쓴다.

---

## 불변 규칙

1. **학생의 명시적 승인 없이 아무것도 보내지 않는다.**
2. **과제 내용을 고치거나, 대신 완성하거나, 채점하지 않는다.** 이 스킬은 제출 절차만 돕는다. 내용 피드백은 review-wild의 몫이다.
3. **AI 사용 내역은 반드시 묻고, 학생의 답을 그대로 적는다.** "사용 안 함"도 정당한 답이다. 학생 대신 추측해서 쓰거나 축소하지 않는다.
4. **제출 시각은 실제 시각을 쓴다.** 마감 전으로 보이게 바꾸지 않는다.
5. **파일 첨부는 하지 않는다.** 제출물은 링크로 보낸다(Google Docs, Drive, Slides 등).
6. 암호·복호화된 주소 취급 규칙은 ask-wild와 같다.

---

## 워크플로

### 1) 제출 패킷 만들기

| 필드 | 내용 | 비고 |
|---|---|---|
| `assignment` | 과제명 또는 과제 코드 | 필수 |
| `team` | 소속 조 (있을 때만) | 프로필에 있으면 그대로. 없으면 `개인`. 반은 자동 |
| `link` | 제출물 링크 | 필수. 여러 개면 모두 |
| `version` | 최종본 / 수정 제출 | 수정 제출이면 무엇이 바뀌었는지 한 줄 |
| `ai_use` | AI 사용 내역 | **필수.** 아래 질문으로 받음 |
| `collaborators` | 함께 작업한 사람 (선택) | |
| `notes` | 늦은 이유, 특이사항 (선택) | |
| `submitted_at` | 제출 시각 | 자동. 아래 명령으로 생성 |

**AI 사용 내역 질문** (학생 언어로, 그대로 묻는다):

> 이 과제를 하면서 AI(Claude, ChatGPT 등)를 사용했나요?
> 사용했다면 **어떤 도구를, 어느 부분에, 어떻게** 썼는지 한두 문장으로 알려주세요.
> 예: "Claude로 개요 아이디어를 얻고, 본문은 직접 썼어요." / "사용 안 함"

**제출 시각** (머릿속으로 계산하지 않는다):

```bash
python3 -c "from datetime import datetime; from zoneinfo import ZoneInfo; print(datetime.now(ZoneInfo('<학생 시간대>')).strftime('%Y-%m-%d %a %H:%M %Z'))"
```

이름과 소속 조는 `profile get`으로 먼저 확인한다(시리즈 공용 프로필). 이름이 없으면 미리보기 뒤의 **학생 안내** 한 번으로 묻고 `profile set --name "…" --team "…"`로 저장한다(소속 조가 없다고 하면 `--team` 없이 저장). **반은 묻지 않는다**(반 암호로 자동으로 정해진다).

### 2) 제출 전 확인

#### 2-1) 공유 설정 검사 (필수, 가장 먼저)

제출 링크마다 **Wild 선생님이 로그인 없이 열 수 있는지** 검사한다. 편집 허용 상태여도 제출할 수 있다.
판정은 스크립트가 하고, Claude는 공유 상태를 수집해 넘기기만 한다.

**적절한 공유 설정 (submit 기준)**

| 서비스 | 통과 | 불통과 |
|---|---|---|
| Google Docs·Sheets·Slides·Drive | 링크가 있는 모든 사용자 (뷰어·댓글 작성자·편집자 모두) / 웹에 게시된 링크 | 제한됨(초대한 사람만) · 특정 조직만 |
| Notion | **웹에 게시된 링크**(`…notion.site/…`, 편집 허용 여부 무관) / Wild 선생님을 초대 | 워크스페이스 링크(`notion.so/…`)인데 초대하지 않음 |
| GitHub | 공개 저장소 / Gist(공개·비밀) / Wild 선생님 계정을 공동 작업자로 초대 | 비공개 저장소인데 초대하지 않음 |
| 그 밖의 서비스 | 로그인하지 않은 창에서 열림 | 로그인 요구 또는 접근 거부 |

**상태 수집 순서**

1. **Google 링크이고 학생의 Drive 커넥터가 있으면** (링크 공개뿐 아니라 Wild 선생님 계정에 직접 공유한 경우도 통과한다. 그래서 설정의 `qna_email`을 `--accept-user`로 넘긴다): 링크의 파일 ID로 파일 권한을 조회하고, 결과 JSON을 그대로 넘긴다. 학생에게 묻지 않는다.

   ```bash
   python3 <skill_dir>/scripts/check_share.py "<link>" --purpose submit --accept-user "<payload의 qna_email>" --permissions-stdin <<'JSON'
   <Drive 커넥터의 파일 권한 조회 결과 JSON>
   JSON
   ```
2. **Notion 링크**: 주소만으로 판정한다. 웹에 게시된 페이지는 `…notion.site/…` 주소를 쓰고, `notion.so/…`는 로그인이 필요한 워크스페이스 링크다. 학생에게 묻지 않고 상태 없이 실행한다. `notion.so` 링크로 불통과가 나왔는데 학생이 Wild 선생님을 직접 초대했다고 하면 `--reported notion_invited`로 다시 판정한다.
3. **그 밖의 경우(Drive 커넥터가 없는 Google 링크, 다른 서비스)**: 먼저 상태 없이 실행해 학생에게 보여줄 선택지(`report_options`)와 확인 방법(`verify_steps`)을 얻는다.

   ```bash
   python3 <skill_dir>/scripts/check_share.py "<link>" --purpose submit
   ```

   학생에게 공유 창에 보이는 상태를 `report_options` 중에서 고르게 하거나, `verify_steps`대로 **시크릿 창에서 링크를 열어 보게** 한다. 학생의 답을 `--reported <상태>`로 넘겨 다시 판정한다.

Drive 커넥터 없이 Google 링크를, GitHub 커넥터 없이 GitHub 링크를 검사하게 되면 **부록 B**에 따라 해당 커넥터 연결을 안내한다(지금 검사는 학생 확인으로 계속).

**판정 처리**

| `verdict` | 행동 |
|---|---|
| `pass` | 다음 체크리스트로 진행 |
| `fail` | 아래 **자동 공유**가 가능하면 먼저 제안한다. 아니면 `reasons`를 그대로 알리고 `fix_steps`를 단계별로 안내하고, 학생이 고쳤다고 하면 **같은 방법으로 다시 검사**한다 |
| `unverified` | 3번 방법으로 상태를 받아 다시 판정한다 |

**자동 공유 (Google 링크 + 학생 Drive 커넥터)**: 결과에 `auto_share`가 있고 학생의 Drive 공유 도구가 있으면, 고치는 방법을 안내하기 전에 먼저 이렇게 묻는다.

> 선생님이 열 수 있도록, 이 파일을 **Wild 선생님 계정에 보기 권한으로 공유**해 둘까요? 다른 사람에게는 공개되지 않아요.

- 동의하면 `auto_share`의 `file_id`, `email`, `role`(`reader`) 그대로 Drive 공유 도구를 호출한다. **다른 대상이나 더 높은 권한으로 바꾸지 않는다**(링크 공개·편집 권한 금지).
- 공유한 뒤 파일 권한을 다시 조회해 같은 명령으로 재검사한다. 통과하면 "선생님 계정에 보기 권한으로 공유했어요"라고 한 줄로 알린다.
- 학생이 거절하거나 공유가 실패하면(파일 소유자가 아님, 학교 계정의 외부 공유 차단 등) `fix_steps` 안내로 넘어간다.

**GitHub 링크**: `--github-user "<payload의 github_username>"`을 함께 넘긴다.

- 학생의 GitHub 커넥터로 저장소 정보를 조회할 수 있으면 공개 여부를 `--repo-visibility public|private|internal`로 넘긴다. 없으면 상태 없이 실행해 `report_options`에서 고르게 하거나 시크릿 창으로 확인하게 한 뒤 `--reported github_public|github_private`로 다시 판정한다.
- Gist(`gist.github.com`)는 공개·비밀 모두 링크로 열리므로 바로 통과한다.
- **비공개 저장소로 불통과**이면 `github_options.ask` 그대로 **두 가지 중 하나를 고르게** 한다.
  1. **공개로 전환**: `option_public` 단계를 안내한다. 공개 전에 비밀번호·개인정보가 없는지 확인하라는 문장은 빼지 않는다.
  2. **Wild 선생님 계정 초대**: `option_invite` 단계를 안내한다. 학생 환경에 `gh` CLI가 있으면(Claude Code 등) 동의 한 번을 받고 `gh_invite_command`를 실행해도 된다. 초대 후 `--reported github_invited`로 다시 판정한다.
- 초대를 고른 경우, **선생님이 수락하셔야 열린다**는 점을 알리고 본문의 공유 설정 칸에 `초대함(수락 대기)`으로 적는다. 마감이 가까우면 공개 전환이 더 확실하다고 한 번 말해 준다.

- 두 번 고쳐도 통과하지 못하면, **그대로 제출할지 멈출지** 학생이 정한다. 그대로 제출하면 미리보기의 "제출 전 확인"에 `공유 설정 ✘ (<reason>)`을 그대로 적는다.
- 링크가 여러 개면 링크마다 검사한다.

#### 2-2) 나머지 체크리스트

하나씩 확인하고, 학생이 직접 확인해야 하는 항목은 물어본다.

| 확인 | 방법 |
|---|---|
| 공유 설정 | 2-1에서 검사함 |
| 최종본인가 | 학생에게 확인 |
| 파일 이름 규칙 | 설정에 `filename_rule`이 있으면 대조한다. 파일 이름은 Drive 커넥터가 있으면 파일 정보에서 읽고, 없으면 학생에게 묻는다. 맞지 않으면 **규칙에 맞는 이름을 그대로 복사할 수 있게 제안**하고, 이름 바꾸기는 학생이 직접 한다. 날짜는 Python으로 구한 제출일을 쓴다. 규칙이 없으면 건너뜀 |
| Wild가 정한 추가 항목 | 설정에 `checklist`가 있으면 항목마다 학생에게 확인 |

통과하지 못한 항목이 있으면 **고칠지, 그대로 제출하고 비고에 적을지** 학생이 정하게 한다. 스킬이 대신 고치지 않는다.

설정값(`filename_rule`, `checklist`)은 `wild_vault.py get`의 `payload`에서 읽는다.

### 3) 미리보기와 승인

```
제목: [submit-wild]<assignment>-[<반 라벨>][<team>][<name>]

Wild 선생님, 안녕하세요. <name>입니다.
<assignment> 과제를 제출합니다.

■ 제출물: <link>
■ 버전: <version>
■ 제출 시각: <submitted_at>
■ AI 사용 내역: <ai_use>
(■ 함께 작업한 사람: <collaborators>)
(■ 비고: <notes>)
■ 제출 전 확인: 공유 설정 ✔ / 최종본 ✔ / 파일명 ✔ <미통과 항목이 있으면 그대로 표시>

— submit-wild로 정리해 제출합니다.
```

영어로 쓸 때는 `Submission / Version / Submitted at / AI use / Collaborators / Notes / Pre-submission check`를 쓴다.
제목 태그 `[submit-wild]`는 항상 유지한다.

**학생 안내 (짧게)**: 첫 미리보기에서 반 라벨·소속·이름이 아직 비어 있으면 빈칸 그대로 보여 주고, 필요한 것만 아래처럼 **한 번에** 묻는다(잠금 여부는 부록 A의 `status`·A-1로 먼저 확인해, 이미 열려 있으면 반 비밀키는 묻지 않는다). 이미 알고 있는 항목은 문장에서 뺀다.

> 제목의 빈칸을 채우려면 **반 비밀키**와 **이름**이 필요해요. 소속 조가 있으면 함께 알려 주세요(없으면 `[개인]`으로 표기돼요).

제목이 어떻게 만들어지는지(반 라벨, 슬롯, 자동 입력 등)는 설명하지 않는다. 학생이 물을 때만 답한다.

### 4) 채널 설정 열기

**부록 A** 절차로 채널 설정을 연다. 대부분은 학생에게 묻지 않고 자동으로 열린다.

submit-wild는 열린 뒤 설정(`filename_rule`, `checklist`)도 함께 읽는다: `wild_vault.py get`.

### 5) 채널 생성과 전송

```bash
python3 <skill_dir>/scripts/compose.py --config <skill_dir>/config/channels.enc.json --skill submit-wild <<'JSON'
{"subject": "[submit-wild] <assignment>", "body": "<미리보기 본문>",
 "fields": {"name": "…", "team": "<소속, 없으면 생략>", "topic": "<assignment>",
            "message": "<version> · 제출 전 확인 결과",
            "link": "<link>", "when": "<submitted_at>",
            "ai_use": "<ai_use>", "details": "<collaborators, notes>"}}
JSON
```

| 순서 | 조건 | 행동 |
|---|---|---|
| ① 메일 커넥터 | 학생의 메일 발송 도구가 있음 | 발송. 초안 도구만 있으면 초안을 만들고 [보내기]를 안내 |
| ② Google Form | ①이 불가하고 `form_url`이 있음 | 미리 채워진 링크 제시. "제출 후 '응답 사본 받기'를 체크하면 증빙 메일이 와요"라고 안내 |
| ③ mailto | ①②가 불가 | 링크와 함께 본문 전체를 복사용으로 제공 |

①을 쓸 수 없어 ②·③으로 넘어가면, **부록 B**에 따라 Gmail 연결을 한 번 안내한다.

**반 라벨과 소속**: 메일·폼·mailto에는 `compose.py` 출력의 `subject`·`body`를 **그대로** 쓴다. `compose.py`에는 제목을 `[<skill>] <주제>`까지만 넘기면, 반 라벨·소속(`fields.team`)·**학생 이름**(`fields.name`)이 자동으로 붙어 `[<skill>]<주제>-[<반 라벨>][<소속>][<학생 이름>]` 형태가 된다(소속 조가 없으면 `[개인]`). 반은 학생이 입력한 반 암호의 슬롯 라벨이므로 **학생에게 묻거나 제목에 따로 적지 않는다.** 본문 끝에는 `(반: <반 라벨> · 소속: <소속 또는 개인>)`, 폼의 Class 칸에는 `<반 라벨> · <소속>`이 들어간다. 그래서 `fields.name`은 반드시 채운다(프로필 이름). 미리보기에서도 이 제목 그대로 보여준다.

### 6) 마무리와 증빙

- 어느 채널로 제출했는지, 제출 시각과 함께 한 줄로 알린다.
- **증빙을 남기도록 안내한다.** 메일이면 보낸편지함의 메일, 폼이면 응답 사본 메일이 제출 기록이다.
- 마감이 지났다면 비난 없이 사실만 적고, 비고에 사유를 썼는지 한 번 확인한다.

| 증상 | 조치 |
|---|---|
| 학생이 파일을 첨부하려 함 | Drive나 Docs에 올리고 공유 링크를 만드는 방법을 안내 |
| `python3` 실행 불가 | 복호화 불가. 본문을 복사용으로 주고, 코드 실행을 켜도록 안내 |
| 종료코드 `3` / `4` | meet-wild·ask-wild와 같음 |

## 부록 A. 채널 설정 열기 (wild-series 공통)

모든 wild 스킬이 같은 절차를 쓴다. `<skill_dir>`는 이 SKILL.md가 있는 폴더, `<skill>`은 이 스킬의 이름(`submit-wild`)이다.

```bash
python3 <skill_dir>/scripts/wild_vault.py status --config <skill_dir>/config/channels.enc.json --skill submit-wild
```

| `state` | 행동 |
|---|---|
| `ok`, `refreshed`, `series` | 열림. 학생에게 묻지 않는다. (`series`는 다른 wild 스킬에서 이미 입력한 반 암호로 열린 것) |
| `no-cache` | **A-1** 학생용 접속 토큰을 스스로 찾는다 |
| `revoked` | "선생님이 이 반 암호의 사용을 중지하셨어요. 새 암호를 받아 입력해 주세요" → **A-2** |

### A-1. 학생용 접속 토큰 찾기 (학생에게 묻기 전에)

**학생용 접속 토큰**은 학생이 반 암호를 처음 입력했을 때 발급되는 한 줄이다: `WILD-TOKEN v3 <series-id> <token>`.
암호가 아니며, 선생님이 그 반 암호를 회수하면 자동으로 무효가 된다. 시리즈 전체(ask·meet·review·discuss·submit)에서 한 줄로 쓰인다.

아래 순서로 찾고, 처음 찾은 곳에서 멈춘다. **학생에게 아무것도 묻지 않는다.**

1. **현재 맥락**: 학생의 개인 선호 설정, Project 지침·파일, 이번 대화.
2. **과거 대화**: 과거 대화를 검색하는 도구가 있으면 `WILD-TOKEN`으로 검색한다.
3. **학생의 Google Drive**: Drive 검색 도구가 있으면 이름이 `wild-series 접속 토큰`인 파일을 찾아 내용을 읽는다.

찾은 줄(여러 개면 모두)을 stdin으로 넘긴다:

```bash
python3 <skill_dir>/scripts/wild_vault.py token import --config <skill_dir>/config/channels.enc.json --skill submit-wild <<'TOKEN'
WILD-TOKEN v3 <series-id> <token>
TOKEN
```

- 성공 → 열림. 학생에게 "저장된 접속 토큰으로 접속했어요" 한 줄만 알린다.
- 종료코드 `3`(회수됨/무효) 또는 아무 데서도 못 찾음 → **A-2**.

### A-2. 반 암호로 잠금 해제

미리보기의 **학생 안내**에서 이미 받았으면 다시 묻지 않는다. 아니면 학생에게 **"Wild 선생님께 받은 반 비밀키를 입력해 주세요"** 라고 요청하고, stdin으로 넘긴다 (명령행 인자로 넘기지 않는다):

```bash
python3 <skill_dir>/scripts/wild_vault.py unlock --config <skill_dir>/config/channels.enc.json --skill submit-wild <<'PW'
<학생이 입력한 반 암호>
PW
```

- 종료코드 `2`(wrong password): 다시 요청. **3회 실패** 시 중단하고 본문을 복사용으로 주며 "Wild 선생님께 암호를 다시 확인해 주세요"라고 안내.
- 성공 → 열림. 출력의 `"suggest_token": true`이면 **A-3**.
- 처음 연 경우 **부록 B**의 "처음 쓸 때" 안내를 한 번 한다.

### A-3. 접속 토큰 발급과 자동 보관

```bash
python3 <skill_dir>/scripts/wild_vault.py token export --config <skill_dir>/config/channels.enc.json --skill submit-wild
```

**학생이 직접 할 일을 최소화한다.** 아래 a는 항상 하고, b는 가능하면 하고, c는 a·b가 모두 불가능할 때만 한다.

| 방법 | 조건 | 행동 | 학생이 할 일 |
|---|---|---|---|
| **a. 대화 기록에 남기기** | 항상 | 발급된 토큰 줄을 이번 대화에 한 번 보여준다: "학생용 접속 토큰이 발급됐어요. 다음 대화에서는 제가 이 기록을 찾아 자동으로 접속할게요." | 없음 |
| **b. 학생 Drive에 저장** | Drive 파일 생성 도구가 있음 | "다음부터 확실하게 자동 접속되도록, 학생님 Google Drive에 토큰 파일을 저장해 둘까요?" **한 번** 묻고, 동의하면 `wild-series 접속 토큰` 문서를 만든다(내용: 토큰 줄 + 아래 설명). 같은 이름의 파일이 있으면 새로 만들지 않고 내용을 바꾼다. 공유 설정은 바꾸지 않는다 | "네" 한 번 |
| **c. 개인 선호에 붙여넣기** | a의 과거 대화 검색 도구도, b의 Drive 도구도 없음 | "설정 → 프로필 → 개인 선호에 아래 한 줄을 붙여 두면 다음부터 자동으로 접속돼요"라고 안내 | 붙여넣기 한 번 |

c로 넘어가면 **부록 B**에 따라 Google Drive 연결도 함께 안내한다(다음부터 토큰을 자동으로 보관·복원할 수 있다).

토큰 파일·안내에 함께 쓰는 설명: "학생용 접속 토큰입니다. 암호가 아니며, 선생님이 반 암호를 회수하면 자동으로 무효가 됩니다. 다른 사람과 공유하지 마세요."

- 학생이 b나 c를 거절하면 다시 묻지 않는다.
- A-1에서 이미 같은 시리즈의 유효한 토큰을 찾았다면 A-3은 생략한다.
- A-1에서 찾은 토큰이 회수되어 A-2로 새로 발급했다면, b로 저장해 둔 Drive 파일도 새 토큰으로 바꾼다.
- Claude Code(로컬)에서는 `~/.wild-skills` 캐시가 유지되므로 `suggest_token`이 `false`이고 A-3을 하지 않는다.

## 부록 B. 커넥터 연결 안내 (wild-series 공통)

커넥터가 연결돼 있으면 Claude가 확인과 처리를 직접 해서 **학생이 할 일이 줄고 결과가 정확해진다.** 그래서 이 스킬은 필요한 커넥터가 없으면 **항상 연결을 안내**한다.

| 커넥터 | 연결하면 자동으로 되는 것 | 쓰는 스킬 |
|---|---|---|
| **Gmail** | 요청·제출을 학생 메일로 바로 발송 (폼·복사 단계 없음) | 전체 |
| **Google Drive** | 공유 설정 검사, 선생님 계정 자동 공유, 접속 토큰 보관 | submit · review (토큰 보관은 전체) |
| **Google Calendar** | 수업일을 읽어 면담 가능한 시간만 보여줌 | meet |
| **GitHub** | 저장소 공개 여부 확인 | submit · review |

**언제 안내하나**

1. **처음 쓸 때**: 채널 설정을 연 직후(부록 A), 이 스킬이 쓰는 커넥터 중 지금 도구 목록에 없는 것을 한 번에 묶어 알린다.
2. **필요한 순간**: 커넥터가 없어 예비 경로(폼 링크, 학생 확인, 시크릿 창 확인, 수업일 직접 고르기 등)로 넘어갈 때, 그 자리에서 "이 단계는 ○○ 커넥터를 연결하면 자동으로 돼요"라고 한 줄로 알린다.

**규칙**

- 같은 대화에서 같은 커넥터는 **한 번만** 안내한다. 학생이 "나중에"라고 하면 그 대화에서는 다시 말하지 않는다.
- 안내 때문에 진행을 멈추지 않는다. **지금 일은 예비 경로로 계속**하고, 학생이 연결한 뒤 원하면 그 단계부터 다시 한다.
- 연결 여부는 Claude의 도구 목록으로 판단한다. 학생에게 "연결돼 있나요?"를 먼저 묻지 않는다.

**안내 문구** (학생 언어로)

> 이 단계는 **<커넥터>** 를 연결하면 제가 직접 확인해 드릴 수 있어요.
> Claude **설정 → 커넥터**에서 <커넥터>를 연결하고, 대화 입력창의 도구 메뉴에서 켜 두면 돼요. 지금은 다른 방법으로 계속할게요.
